# 废土过载 · OVERLOAD

> 2–8 台废土机甲，没有血条，只有温度。把对手烤到 100° 过载，看他当场短路爆炸。

一个可以直接在浏览器里开房的实时机甲乱斗原型：单进程 Node 服务器 + WebSocket 权威同步，前端 three.js。
没有账号、没有外部素材、没有 CDN —— 断网局域网也能玩。

---

## 快速开始

```bash
npm install
npm run dev          # 构建 public/app.js 并启动服务器
```

打开 <http://localhost:3000>。

- **第一次玩**：点菜单里的「新手教程」。它在本地跑一局练习（不连服务器），
  六步带你走完移动 → 开火 → 冲刺 → 技能 → 过载散热 → 道具，两个训练靶站着不动给你打，
  每一步做完自动打勾，随时可以「跳过这一步」或「退出教程」。
- **单机/试玩**：点「快速开战」，AI 会立刻补齐对手。
- **和朋友玩（同一局域网）**：主机运行 `npm run dev`，把终端里打印的 `局域网: http://192.168.x.x:3000`
  发给朋友；朋友打开后点「加入房间」→ 填房间码，或直接贴主机地址（默认同源，无需填写）。
- 主机也可以点「创建房间」，在等待大厅里调模式、AI 数量、地图、事件频率、过载速度、AI 难度，
  其他人输房间码进入，房主点「开始战斗」。

> 服务器监听 `0.0.0.0`。端口可用 `PORT=8080 npm run dev` 修改。
> 防火墙需要放行该端口，WebSocket 与页面同源。

## 模式一览：教程 / 射击训练 / 进阶训练 / 对战

| 入口 | 内容 |
| --- | --- |
| **新手教程**（菜单） | 两个不会动的训练靶 + 六步：走路 → 开火 → 冲刺 → 技能 → 过载散热 → 捡道具 |
| **射击训练**（菜单，新） | 射击篇五步：固定靶 → 移动靶（提前量）→ 远靶（11 m 外）→ 点射控温 → 会还手的实战靶机；面板实时显示**命中率**与热量 |
| **进阶训练**（菜单） | 两台**会走会打**的 AI（只盯你一个人），五步练真打法：冲刺躲弹 → 反弹弹命中 → 边打边降温 → 抢补给 → 击倒 AI |
| **快速开战** | 4 人混战，AI 难度「简单」（房主可在创建房间里改） |

打不中人先打**射击训练**（射击篇），会打人但活不下来再打**进阶训练**：
两者都是单机练习场，不影响战绩，每一步都有具体目标、提示和实时反馈。

## 射击训练（射击篇）

菜单「射击训练」。一局本地靶场：三个木头靶 + 一台最后才醒的实战靶机。

| 步骤 | 你要做的事 | 为什么 |
| --- | --- | --- |
| 1 打固定靶 | 击毁正前方的红色固定靶 | 建立「准星 = 弹道」的直觉 |
| 2 打移动靶 | 命中左右横移的黄色靶 3 次 | 学会预判提前量 |
| 3 远距离射击 | 命中 11 m 外的紫色远靶 2 次 | 子弹要飞一会儿，距离越长提前量越大 |
| 4 点射控温 | 热量 ≤ 60 时命中 4 次（超过 75 连击清零） | 学会松开左键，别把自己点短路 |
| 5 实战靶机 | 击倒 1 台会走、会还手的橙色 AI | 把前四步合起来用 |

面板会实时显示 `命中 N / 射击 M · 命中率 X% · 热量 Y`。五步走完按钮变灰，
下次还能再进（练手感）。

## 手感（看得清 / 打得快）

- **射击零延迟感**：按下左键的同一帧，你自己屏幕上就出现枪口火光、后坐、声音和一枚
  **预测弹**；服务器确认的子弹到达后无缝接管，不会出现两发。
- **输入立刻上行**：开火 / 冲刺 / 技能 / 道具 / 换方向不再等 30 Hz 的输入节拍，按下就发。
- **小局更快同步**：人数 ≤ 4 的对局用 **30 Hz 快照**（大场仍是 20 Hz，保证带宽）。
- **来袭预警**：有子弹会打中你时，脚下亮起红色弧线指向来袭方向，配一声轻提示音。
- **准星永远跟着鼠标**：瞄准点每帧按「鼠标 + 当前相机」重新投影，走过一段路之后准星也不会
  指向旧的世界坐标；机甲身体也跟着准星转（以前边走边打会朝行走方向，看着像没跟鼠标）。
- **撞墙不再卡进墙里**：碰撞解析对每类碰撞体多做几轮，遇到比机甲还窄的夹缝（钢板贴着墙）
  会拒绝这次移动，而不是把机甲塞进墙里半米。
- 快速开战默认的 AI 难度调成「简单」（创建房间可自选），新手不至于一进场就被集火。

## 命中反馈与子弹颜色（新）

- **子弹用射出者的颜色**：谁开火就飞谁的颜色（自己 = 你选的颜色，AI = 它的机体色），
  拖尾、光晕、命中火花全部同色 —— 一眼看得出这颗弹是谁打的、要不要躲。
  蓄力弹保留白热核心，轨道弹保留粉色，方便区分弹种。
- **命中当帧可见**：子弹在画面上碰到机甲的那一帧就炸开（亮闪 + 地面冲击环 + 火花 + 尘土），
  不用等服务器回包；服务器确认后再补一个 `+8` 伤害数字和准星命中提示，不会重复爆炸。
- 打墙、打钢板、反弹也都有撞击特效，反弹命中是绿色数字。

## 核心规则

- **没有 HP**。所有伤害都转化为 **过载 0–100**。一发普通电磁弹 +8 过载，蓄力弹 +14，
  也就是说满热之前能吃 **12 发以上** 干净命中；自然散热为 2.5 秒未受热后每秒 -2.6，
  散热区每秒 -18。站着不动也能慢慢退烧。
- 过载 **≥100** 立刻短路爆炸：本人出局，爆炸波及周围（+24 过载，可连锁），**10 秒后重生**
  （重生后 2 秒无敌）。
- 过载越高越慢（70+ 移速 -10%，90+ -15%），并伴随电流声与视野抖动。
- 降温手段：地图中央与四周的**散热区**、**冷却罐**道具、**冷却液泄漏**事件、走位躲伤害。
- 每局默认 **180 秒**；**最后 30 秒电磁终结**：风暴区域扩张、全场持续升温。
- 计分：击杀 +1，被击杀 -1；结算按比分排名，并给每个人一个搞怪称号。

## 技术实现

```
shared/     纯逻辑：常量 / 机体 / 地形生成 / 运动积分（前后端共用）
server/     权威模拟 MatchSim（60 Hz）、Bot AI、房间与房间码、静态文件 + WS
src/        浏览器端：three.js 场景、机甲模型、特效、HUD/菜单、预测与快照和解
scripts/    esbuild 构建 + 无头测试（sim / UI / game / 全链路 e2e）
public/     index.html / style.css（构建产物 app.js 不提交）
```

- 服务器 **60 Hz** 固定步长模拟，**20 Hz** 快照；本地预测 + **回放式和解**（自己的机甲），
  **快照插值**（别人和 AI），输入 30 Hz 上行。
- 传输用 WebSocket（原 GDD 写的是 UDP，但要在浏览器里直接开房只能这样）；
  仍然是主机权威、无账号、局域网可用。
- 断线重连：客户端保存 token，重连后自动回到原席位与进行中的对局。
- 断线玩家的机甲会被 AI 接管，避免 3v3 变 2v3。
- 无外部图片/字体/音频：地面、钢板、天空、烟雾、图标、音效全部程序化生成。
- 帧率过低时自动降画质（关辉光/阴影），设置里也可以手动切「低」。

## AI / 其他玩家看起来一卡一卡的？

服务端每秒只发 20 次状态（20 Hz），如果客户端收到一次就摆一次位置，别人和 AI 的机甲就会
「动一下 → 停 50 毫秒 → 再动一下」；原来那套平滑滤波又和目标位置的推算打架，于是变成
「卡顿 + 突然弹一下」。现在改成标准的快照插值：

- 每个远程单位保留最近 1.2 秒的快照（位置/速度/存活），按**渲染时钟**在相邻两个快照之间插值，
  所以每帧都在动，速度和服务端一致；
- 渲染时钟只会以最多 12% 的速度追赶/放慢，永远不会跳变；遇到掉帧（长帧）也不会把机甲"瞬移"一段；
- 插值延迟按网络抖动自动调整（60–200 ms，局域网一般 60–80 ms），
  抖动大就多缓冲一点，宁可多等一帧也不卡；
- 丢包时用最后的速度外推最多 300 ms，再断流就原地停住，不会往回弹。

`npm run botmotion` 就是这项的回归测试：真实 `Game` + 真实 `MatchSim`，统计「渲染出来的速度 / 真实速度」
和「画面相对渲染时钟的误差」。30/120 ms 延迟、30/60 fps、含 150 ms 卡顿的情况下，
渲染速度比 1.00、逐帧误差 1–3 cm，卡顿帧和弹跳帧基本为 0。

## 移动被拽回？

联机时如果机甲「走两步又被拉回原地」，那是客户端预测和服务端快照在打架。现在用的是回放式和解：

- 每条输入带序号，客户端把本地模拟过的**每一帧**都记下来；
- 快照里带回「服务端处理到第几个输入了」（`seq`），客户端从服务端的权威位置出发，
  把还没被处理的那几帧重新跑一遍 —— 得到的是「按同样的操作，我应该在哪」，
  而不是拿现在的预测位置去和几帧前的位置比（那样差值就等于延迟 × 速度，必然往回拽）；
- 修正量不会直接跳到屏幕上：先记成一个偏移，每帧最多回收 2 cm，所以最多是
  「稍微落后一点」，不会再被拽回去；
- **冲刺**按下时就本地预测，服务端确认后无缝接上；斜向冲刺服务端也做了归一化
  （以前斜着冲比直着冲远 41%）；
- **出生点**由服务端下发，开局不会再有 30 米瞬移；倒计时期间按下的技能/冲刺不会留到开局才放。

`npm run nettest` 就是这个问题的回归测试：用真实 `Game` + 真实 `MatchSim` 接一个带延迟和抖动的假网络，
统计「服务端在前进、屏幕却在后退」的帧数。20 / 70 / 120 / 140 ms 单程延迟（含抖动）下都是 **0 帧**，
位移和冲刺次数与服务端一致，站住不动时逐帧位移 0.000 m。

## 帧率不够？

从最省事到最彻底，按顺序试：

1. **对局中直接点 HUD 右上角的「画质 中/高/低」** —— 一键循环切换，立即生效并记住。
2. **设置 → 画质**：`高 / 中 / 低`。
   - 高：阴影 1024 + 半分辨率辉光，像素比上限 1.5
   - 中（默认）：阴影 512 + 1/3 分辨率辉光，像素比上限 1.15
   - 低：关阴影、关辉光、关尘埃与装饰道具、关 CSS 混合模式/毛玻璃
3. **设置 → 渲染分辨率**：100% / 85% / 70% / 55%。高 DPI 屏幕上这是最有效的一档。
4. **设置 → 帧率上限**：默认 60。144 Hz 屏幕不限制时 GPU 会被无意义地跑满。
5. 帧率低于 40 持续几秒会**自动降档**（高 → 中 → 低），并在 HUD 提示；不会自动升回去。

也可以在地址栏强制：`?quality=low&scale=0.7`（还可加 `?noaudio=1` 静音）。

**诊断**：主菜单点「诊断」，能直接看到 FPS、画质档位、渲染缓冲尺寸、draw calls、三角面数、GPU 名称、自动降档次数。

工程侧的优化（已内置）：

- 静态场景层（地面/网格/边界/散热区/酸液/钢板/塔）在雷达图上只绘制一次并缓存，每帧只贴图 + 画动态单位
- HUD 全部做脏值检查（只在数值变化时写 DOM），元素查询走缓存
- 准星、瞄准射线、小地图刷新按档位限频；Raycaster/Vector 复用，无每帧分配
- 辉光在后处理里以 1/2 或 1/3 分辨率渲染；阴影贴图按档位 1024/512/关
- 低档跳过环境尘埃、装饰道具、动画细节与 CSS 毛玻璃
- CPU 侧每帧开销：`game.update` ≈ 0.2 ms、快照应用 ≈ 0.1 ms（`npm run perf`）
- **灯光预算固定 6 盏**：场地里的散热区 / 电磁塔 / 探照灯都改成「光源点位」，由一小池
  点光源跟随镜头最近的 6 个点位；机甲自身不再带点光源。
  - 以前每台机甲一盏，4 人局 + 大地图会有 **30 多盏点光源**，每个像素都要循环一遍；
  - 更糟的是有人死亡 / 重生时灯光数量变化，three.js 会**重编译整个场景的着色器** ——
    这就是「重生后突然卡一下」和「四人局特别卡」的来源。现在灯光数量恒定，永不重编译。

## 已知限制

- 这是原型而不是成品：没有账号、匹配、排行榜或反作弊；房间码即邀请。
- 浏览器需要支持 WebGL2；很低端的设备建议把画质切到「低」。
- 服务器是单进程内存态：重启后房间与对局都会消失。
- 移动端未适配（GDD 目标平台是 PC）。
